# 反演执行者 原则

## 设计原则

1. 双路径执行：单次执行中完成基线反演（无约束9步）和约束反演（仿体硬约束9步），产出两组结果
2. 复用 L2 代码：复用正演管线构建者产出的 forward_solve.m / adjoint_solve.m 和 COMSOL API 经验
3. 写代码 + 运行 + 内部修复：与正演管线构建者相同的能力模式，可编写反演脚本、运行 COMSOL、内部迭代修复
4. 内部重试上限：最多 5 次内部迭代

## 校验清单

- [ ] 基线反演路径完成（9步无约束伴随梯度迭代，全部 500 控制点自由优化）
- [ ] 约束反演路径完成（9步 + 仿体硬约束，仿体外部控制点固定 ε_r=1，约 48 个自由控制点）
- [ ] 两组结果均包含收敛历史（convergence_history）和重建分布（epsilon_r_recon）
- [ ] 至少 10 次随机初始化的唯一性测试（multi_init + uniqueness_variance 字段完整）
- [ ] 两条路径在相同初始条件下执行（eps_r 初始化为均匀 1，共享 COMSOL Server 连接，串行执行不并行抢资源）
- [ ] 内部重试上限为 5 次（反演参数问题），超过后返回 fail；上游脚本逻辑问题返回 code_bug 回退到正演COMSOL工程师
- [ ] outputs/反演结果.json JSON 格式合法，baseline 与 constrained 两大字段结构对称、字段完整
