# 逆散射科研闭环规范

> 注入目标：假设提出者、算法实现者、实验执行者、结果分析者、基线评估者、管线优化者
> 用途：为本 App 全部 6 个角色提供科研闭环四阶段的统一认知框架，确保假设→验证→分析→新假设的迭代路径可追溯、可复现、无静默错误传播

## 目的

逆散射算法研究的核心价值流是**科研闭环**：假设 → 验证 → 分析 → 新假设。这条闭环不是线性流水线，而是一个**受控反馈循环**——每一轮迭代的产出（Δ 基线对比 + 改进信号）驱动下一轮假设的生成。如果任一阶段的产出物缺失、不可追溯或含静默错误，闭环就会退化为"无方向的开环迭代"或"基于错误数据的无效推理"。

本规范解决三个根本问题：
1. **阶段边界**：每个角色必须知道自己的产出物是什么、输入来自谁、输出流向谁——否则跨阶段数据竞争。
2. **闭环回归信号**：M5 的改进信号是 M1 生成新假设的唯一合法驱动源——否则闭环退化为开环。
3. **可追溯性**：每一轮迭代的假设记录、代码版本、实验配置、分析结果必须可事后追溯——否则科研结论不可证伪。

## 核心准则

### 准则 1：闭环四阶段拓扑不可删改——M1→M2→M3→M4→M5→M1

**Why 推理链**：
科研方法论（Scientific Method）的经典闭环是"假设→实验→分析→新假设"（Popper 可证伪性原则）。本 App 将其映射为 M1（假设）→ M2（实现）→ M3（实验）→ M4（分析）→ M5（评估）→ M1（新假设）。每个阶段的输入严格依赖上一阶段的产出：M3 实验 diff 依赖 M2 实现，M5 评估依赖 M4 分析。**删改任一阶段都会使闭环断裂**——例如删掉 M4，M5 无法获得三件套指标，改进信号失去数据支撑。

**When not**：
- 非科研迭代场景（如纯工程管线构建）不需要四阶段闭环——但本 App 明确定位为科研研究 App，不适用此豁免。
- M6 管线优化者是支线，**不在闭环四阶段内**——它独立于 M1~M5 主线，不参与闭环回归。

**省略后果**：
- 删掉 M1 → 无假设入口，闭环死锁在"无假设"状态。
- 删掉 M4 → 三件套需手工计算，静默错误无检测传播到 M5，研究者基于错误指标迭代。
- 删掉 M5 → 无改进信号，闭环退化为开环，研究者失去客观改进方向。

**认知科学基础**：
确认偏差（Confirmation Bias）——研究者倾向于寻找支持自己假设的证据。闭环四阶段将"假设"与"验证"分离到不同角色（M1 vs M3），消除同一人既提假设又判结果的偏差。

### 准则 2：同一假设内严格串行——禁止同假设并行

**Why 推理链**：
同一假设的生命周期内，M1→M2→M3→M4→M5 必须严格串行。这是数据依赖的必然要求——M3 实验执行的输入是 M2 产出的代码 diff，如果 M2 和 M3 并行，M3 读到的是半成品代码。经典并发理论中，**有数据依赖的操作不可并行**（Bernstein 条件）。

**When not**：
- 不同假设之间可以并行（H001 的 M4 分析阶段与 H002 的 M2 实现阶段并行），因不同假设通过 per-hypothesis L1 代码快照隔离（详实验与快照协议）。

**省略后果**：
- M2/M3 并行 → M3 读到半成品代码，实验结果不可复现。
- M4/M5 并行 → M5 基于未完成的分析报告做对比，exceeds_baseline 判定无意义。

### 准则 3：单一编排入口——引擎 DAG 驱动全链

**Why 推理链**：
APP 的 app.yaml edges 定义了 M1→M2→M3→M4→M5 的自动串联拓扑。研究者只需确认 M1 的假设，引擎自动按 edges 依次执行 M2~M5。M6 管线优化者不在主线链中，由研究者手动触发。

**省略后果**：
- 拆分为多编排 → 研究者需手工拼接角色间数据传递，闭环可追溯性丧失。

### 准则 4：闭环回归信号必须来自 M5——改进信号是新假设的唯一合法驱动源

**Why 推理链**：
M5 基线评估者产出"改进信号"（Δ 对比报告 + exceeds_baseline 判定 + 是否值得启动新假设的建议），这是 M1 产出"新假设触发决策"的唯一合法输入。如果 M1 不基于 M5 信号而是凭空生成假设，闭环退化为"随机搜索"而非"受控迭代"——经典优化理论中，无梯度/无反馈的搜索是随机游走（Random Walk），收敛性无保证。

**When not**：
- 首轮假设（H001）的输入是初始研究问题，无前置 M5 信号——这是闭环的冷启动边界。

**省略后果**：
- M1 凭空生成假设 → 闭环退化为随机搜索，研究者无法判断"哪个改进方向有效"。

### 准则 5：pipline 是持久化科研资产——所有角色直接操作

**Why 推理链**：
`COMSOL/pipline/` 是科研项目的持久化资产，所有角色直接读写该目录。代码演进通过 git 版本控制实现累积式、可追溯的持久化。M2 算法实现者负责算法目录的改动，M6 管线优化者可维护全部 pipline 代码。实验快照通过 git tag 实现，无需文件拷贝。版本控制天然解决了跨实验对比的基准问题。

**When not**：
- M6 的维护范围可覆盖 pipline 全部目录，但不得触及算法参数/逻辑（那是 M2 的职责）。
- 新几何类型/新求解器需要大幅扩展时，通过 git 分支管理。

**省略后果**：
- 无版本控制 → 代码改动不可追溯，跨实验对比失去共同基准。

### 准则 6：三件套指标是科学结论的唯一量化锚点

**Why 推理链**：
逆散射算法的质量评估使用三件套指标：cos θ（角度一致性）/ F_cheb（Chebyshev 残差）/ PASS 项数（A12=5/7、C01=4/6 场景的通过率）。这三个指标是科研结论的量化锚点——如果指标计算基于静默错误数据（NaN/Inf/越界/不可重复），研究者会基于错误指标产出无效科学结论（比崩溃更危险，因崩溃至少可被察觉）。

**When not**：
- result_status 非 VALID 时（EMPTY/DIVERGED/NOT_CONVERGED/INVALID/NON_REPRODUCIBLE/BENCHMARK_DEVIATION），三件套不计算或降级处理。

**省略后果**：
- 基于静默错误的三件套迭代 → 无效科学结论，比崩溃更危险。

## 判别清单

每个角色执行本职前，逐项核对：

- [ ] 当前假设的 hypothesis_id 已在 hypothesis_chain.json 中注册且全局唯一？（M1）
- [ ] 代码 diff 仅触及 pipline 算法目录（core_jhyp/ core_adjoint/ core_inversion/ algorithm/）？（M2/M6）
- [ ] modification_log.md 已写入本次修改条目（含时间戳/文件/diff 摘要）？（M2/M6）
- [ ] experiment/<exp_id>/ 子目录已创建，exp_id 全局唯一？（M3）
- [ ] config_snapshot.json 含物理参数七字段 + 与基线 diff + l1_code_hash + l1_code_diff + validation_phase？（M3）
- [ ] git tag exp_<exp_id> 已标记当前代码版本？（M3）
- [ ] NaN/Inf 检测 + 值域断言已执行且通过？（M4）
- [ ] result_status 非 VALID 时已正确降级处理？（M4）
- [ ] M5 的改进信号基于 M4 分析结果（result_status=VALID 或 NOT_CONVERGED），不基于 EMPTY/DIVERGED？（M5）
- [ ] 改进信号已产出并传递给 M1 驱动新假设触发决策？（M5）

## 反模式

1. **跨阶段数据竞争**：M2 和 M3 并行执行同一假设 → M3 读到半成品代码，实验结果不可复现。后果：config_snapshot.json 记录的 git_commit_hash 与实际运行代码不一致。
2. **开环迭代**：M1 凭空生成假设，不基于 M5 改进信号 → 闭环退化为随机搜索。后果：研究者无法判断改进方向有效性，科研迭代效率趋近于穷举。
3. **静默错误传播**：M4 跳过 sanity_check.m 直接计算三件套 → NaN/Inf/越界结果无检测进入 M5 基线对比。后果：exceeds_baseline 判定基于错误数据，研究者产出无效科学结论（比崩溃更危险）。
4. **pipline 版本失控**：pipline 代码无 git 版本控制 → 改动不可追溯，跨实验对比失去共同基准。
5. **闭环断裂**：M5 未产出改进信号或信号未传递给 M1 → 闭环在"新假设触发"阶段断链。后果：科研迭代停止，研究者失去客观改进方向的信号源。
