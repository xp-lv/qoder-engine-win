# 基线资产参考

> 注入目标：结果分析者、基线评估者
> 用途：为 M4 结果分析和 M5 基线评估提供固化基线数值、三件套指标定义、基准解参考资产的使用规则和降级策略，确保 Δ 对比有客观基准、三件套计算有值域约束、benchmark 交叉校验有参照解

## 目的

基线资产（baseline/）是科研闭环的**客观锚点**。M5 的 Δ 对比 = 迭代值 − 基线值——如果基线值漂移或被篡改，exceeds_baseline 判定无意义。M4 的 benchmark 交叉校验依赖 benchmark_solution.json 的参照解——如果参照解缺失或 physics_params_hash 不匹配，静默错误无第二道防线检测。

本参考解决三个根本问题：
1. **基线固化**：三件套基线 + 物理参数基线是只读资产，不可漂移——否则跨实验对比失去共同基准。
2. **指标定义**：三件套指标（cos θ / F_cheb / PASS 项数）有确定值域，越界即静默错误。
3. **参照解可用性**：benchmark_solution.json 仅对基线球型几何有效，非球场景需降级标注。

## 核心准则

### 准则 1：三件套基线固化——A12=5/7 / C01=4/6 / cos θ=0.9929，只读不可漂移

**Why 推理链**：
三件套基线是逆散射算法质量的固化参照点。A12（5/7 PASS）和 C01（4/6 PASS）是两个标准测试场景的通过率，cos θ=0.9929 是角度一致性基准。M5 的 Δ 对比以这些值为基准——如果基准值随迭代漂移（如某次实验意外覆写 baseline/metrics_baseline.json），"是否超越基线"的判定变成移动靶，科研结论不可重复。

**When not**：
- 多几何场景（非基线球型）的基线值不同——当前基线仅对 REQ-010 基线物理参数有效，非球场景需版本分支 + 新基线。
- 基线值本身需要更新时（如 SDK 升级导致基线重算），走版本分支（不原地修改）。

**省略后果**：
- 基线漂移 → Δ 对比无意义，exceeds_baseline 判定不可重复。
- 基线丢失 → M5 无法执行基线对比，闭环在"评估"阶段断链。

### 准则 2：物理参数基线固化——r/R/f/λ/ka/方向数/体素数

**Why 推理链**：
物理参数基线定义了逆散射问题的"标准设定"：r=0.13m（散射体内径）、R=0.26m（外径）、f=1 GHz（频率）、λ=30cm（波长）、ka=2.72（波数×半径，无量纲）、64 Fibonacci 方向（入射方向数）、19268 体素（其中 673 内层）。这些参数定义了正演/反演的物理域——如果实验使用的物理参数与基线不一致，三件套指标不可直接对比（因物理域不同）。

**When not**：
- 参数变更有版本/分支（REQ-010 AC3）——新建 experiment/<exp_id>/ 分支记录 diff，不覆盖 baseline/physics_params.json。
- config_snapshot.json 记录"与基线 diff"字段，使参数差异显式可追溯。

**省略后果**：
- 物理参数不一致的实验做三件套对比 → 因果推断失效（指标差异来自参数差异而非算法差异）。

### 准则 3：三件套指标值域断言——cos θ∈[-1,1] / F_cheb≥0 / PASS∈[0,total]

**Why 推理链**：
三件套指标有物理确定的值域：cos θ（余弦相似度）∈ [-1, 1]，F_cheb（Chebyshev 残差）≥ 0，PASS 项数 ∈ [0, total]。如果计算结果越界（如 cos θ=1.5 或 F_cheb=-0.3），说明上游正演/反演产出了静默错误数据。值域断言是 sanity_check.m 的必选项（不可关闭），在 compute_three_piece.m 之前拦截——这对应防御性编程的"前置断言"原则。

**When not**：
- 无豁免——值域断言是 IF-8 必选项，任何配置都不能关闭。

**省略后果**：
- 值域断言缺失 → cos θ=1.5 这样的物理不可能值进入 M5 基线对比，exceeds_baseline=true（因 1.5 > 0.9929），研究者误以为算法改进有效。

### 准则 4：result_status 状态机——VALID / EMPTY / DIVERGED

**Why 推理链**：
实验结果有 3 种状态：
- VALID：健全性校验通过（NaN/Inf 检测 + 值域断言），三件套可计算。
- EMPTY：正演/反演输出空矩阵，跳过三件套。
- DIVERGED：NaN/Inf 发散或值域越界。

状态机保证 M5 只在 result_status=VALID 时执行基线对比——EMPTY/DIVERGED 不进入 M5。

**省略后果**：
- 状态机缺失 → DIVERGED 结果进入 M5，exceeds_baseline 基于发散数据判定，研究者迭代方向错误。

## 判别清单

### M4 结果分析者
- [ ] 三件套仅在 result_status=VALID 时计算？
- [ ] result_status=EMPTY 时跳过三件套，分析报告记录"实验未产出有效数据"？
- [ ] result_status=DIVERGED 时已在入口拦截？
- [ ] 值域断言（cos θ∈[-1,1]、F_cheb≥0、PASS∈[0,total]）在三件套计算之前执行？

### M5 基线评估者
- [ ] 仅 result_status=VALID 的结果进入基线对比？
- [ ] result_status=EMPTY/DIVERGED 不进入 M5？
- [ ] Δ = 迭代值 − 基线值，基线值取自 baseline/metrics_baseline.json（只读）？

## 反模式

1. **基线漂移**：M5 修改 baseline/metrics_baseline.json → Δ 对比基准移动。后果：exceeds_baseline 判定不可重复，跨迭代对比失效。
2. **值域越界未拦截**：cos θ=1.5 直接进入三件套计算 → exceeds_baseline=true（1.5 > 0.9929）。后果：研究者误判算法改进有效，实际是静默错误。
3. **DIVERGED 进入 M5**：M4 未拦截 NaN/Inf 结果 → M5 基线对比基于发散数据。后果：exceeds_baseline 判定无意义，改进信号指向错误方向。
